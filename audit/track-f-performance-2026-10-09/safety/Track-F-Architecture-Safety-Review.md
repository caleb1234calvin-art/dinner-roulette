## Dinner is a useful UX comparator, not equivalent provider work

Dinner executes one union query covering five food amenity selectors, one sequential provider chain (continues to later mirror on valid-empty), bounded20s budget/8s attempts. Date Night builds up to four category groups (seasonal, entertainment, culture, outdoor), parallel groups with hedged mirrors starting1500ms apart and shared20s budget. Date Night includes lifecycle-context negative queries in every group and seasonal contextual/prose clauses when selected. Same mirror list does not mean same server cost, density, result bytes, timeout probability or recall. Dinner also has different curated/fallback merge behavior; its component refetches on radius change and is not itself a 50-mile session implementation.

## Testable release prerequisites for a future alternative

- Compare exact normalized identity sets and categories at fixed radius/clock/season, not raw venue counts alone. Retain provider outcomes and cancellation separately.
- Reuse/adapt date-night-cache tests: valid-empty supersession, equal-time freshness, cache bounds, cross-category negative evidence, TTL non-rejuvenation, larger→smaller reuse, incompatible signatures.
- Add unpatched negative-eviction regression for both entry and aggregate-venue eviction, with positive/negative arrival orders and identity aliases. Fix source behavior only in separately authorized candidate.
- Add nonpatch upstream abort propagation tests; ensure provider-body parse is aborted and budget-bounded even if browser replacement already succeeded.
- Repeat discovery-client-lifecycle and radial-session equivalents: late abort-ignoring results, origin changes, unmount, radius up/down during request, season toggle, explicit retry, no runaway loop.
- Repeat seasonal-completeness-v1, overnight-final-end, late-fall-client-cache, rideshare-precision, identity receipt/favorites/exclusion, exact cutoffs±1ms, resume,2027 and ordinary Date Night regressions.
- Curated-first prototype must show no provider-health implication, strict radius eligibility, no stale current-policy data, and immediate removal on negative evidence/expiry; do not silently treat saved-only results as acquired category coverage.
- Measure initial/local radius/filter latency and memory against real payload sizes;20,000 raw-venue cap is an eviction bound, not a measured byte/CPU budget. Large 50-mile identity dedupe loops and React decoration can have client cost.
- Complete hosted/browser/layout checks for exact final future candidate. Current audit measurements alone do not transfer release approval.
