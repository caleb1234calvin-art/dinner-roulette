# Pick For Us: short physical test card

Use this only after the exact website release is separately approved, published and checked. It is a prepared checklist; none of these new-release cases has passed yet.

## Before you start

- Test while stationary and free to stop. Phone first; Galaxy Tab A7 Lite SM-T220 when available.
- Do not install the PR80 or PR81 debug APK over the existing new-package app. PR78, PR80 and PR81 have different signing certificates. Do not uninstall or clear data to get around a conflict.
- Prefer the existing confirmed wrapper for the new hosted footer/legal checks. Record its actual provenance separately from the new website commit. It loads the live website; it does not contain the unpublished candidate.
- Record model, Android/WebView version, time, selected app/build evidence and website release/date. No serial number or precise location is needed.

## Short run

1. Note one saved item/preference in the selected wrapper and any older app. Leave both intact.
2. Cold-open online. Check Home, Dinner, Nightlife, Casino and Date Night; try a manually chosen city.
3. Check the footer on those pages, Settings and a result/options/plan flow in both themes. Is it readable, reachable and clear of system bars/keyboard? Does artwork actually appear?
4. From the wrapper, open Privacy and Terms. Check version 1.0, the approved actual date, full text, contents links, history, contact and Back. No login should be needed.
5. Open Support. Check causticrelay@gmail.com; cancel without sending. Try a Maps/venue link and return without starting navigation, ordering or booking. Record any missing handler.
6. Close/reopen and background/resume. Check saved state and old-app data. Do not press “Clear favorites and history.”
7. If safe and agreed, test offline launch → reconnect → Retry, then interrupted search → reconnect. If the black-screen/cross-app connectivity symptom returns, stop and record the sequence. Do not change VPN/security settings or erase data to fix it.
8. Check portrait/landscape, Back and keyboard. Test denied/approximate/precise location and TalkBack/large-text only when available and within the agreed permission/settings scope. Unrun cases stay unrun.

Repeat on the SM-T220 when available. Do not infer its result from the phone or assume its GPS capabilities from “Wi-Fi-only.”

Stop on suspected data loss, crash/blank screen, an unexpected replacement/security prompt or trapped navigation. Send the step, what happened, time and an optional redacted screenshot. A simple reply format is:

Device and Android/WebView; step; PASS / FAIL / BLOCKED / NOT RUN; what you saw.

These observations can accept the tested hosted footer/legal behavior on the recorded wrapper. They do not certify an exact new APK, a same-package signed update, Play distribution or all accessibility cases.
